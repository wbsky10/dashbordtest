# 経営層向けタスク管理ダッシュボード 取扱説明書

社長・役員が「1画面で会社全体の状況を把握し、気になるプロジェクトだけをワンクリックで掘り下げられる」経営ダッシュボードです。

---

## 📌 3つの特徴
1. **インストール・サーバー不要**: ブラウザで `index.html` をダブルクリックするだけで動きます。
2. **保守が簡単（非エンジニア対応）**: 毎週の更新は **`data.js` 1ファイルだけ** を編集するだけ。HTMLやCSSを触る必要はありません。
3. **外部通信なしの完全ローカル動作**: 機密情報が外部に送信される心配が一切ありません。

---

## 📁 ファイル構成

```text
dashboard/
├── index.html     … 画面の骨組みと表示プログラム（編集不要）
├── style.css      … 画面デザイン・印刷用レイアウト（編集不要）
├── data.js        … ★担当者が編集するデータファイル（ここだけ編集！）
├── firebase.json  … Firebase Hosting の設定ファイル（設定済み）
├── .firebaserc    … Firebase プロジェクトID連携ファイル（設定済み）
├── deploy.bat     … Windows用ワンクリックデプロイツール
└── README.md      … 本マニュアル
```

## 🔄 毎週の更新手順（週次ルーティン 5ステップ）

毎週金曜夕方や月曜朝の定例報告に向け、以下の手順で更新します。

1. **`data.js` を開く**
   - Windows付属の「メモ帳」や、VS Codeなどのテキストエディタで `data.js` を開きます。
2. **日付の更新**
   - `updatedAt`（画面右上に表示される日付）を今週の日付に書き換えます。
   - `baseDate`（自動判定の基準日）を今週の日付（例: `"2026-11-04"`）にします。
3. **先週比データの移行**
   - `lastWeek`（先週の数値）に、前回の数値を入力します。
   - `completedTasksThisWeek`（今週の完了タスク数）を更新します。
4. **各セクションの更新**
   - 「経営判断が必要な事項」に、役員に決めてほしい事項を追加・削除します。
   - 「プロジェクト一覧」の進捗率、期日、ひとこと、リスク・タスクを更新します。
   - 「担当者別の負荷」のタスク数・超過数・負荷率を更新します。
5. **保存して画面を確認する**
   - `data.js` を上書き保存（`Ctrl + S`）します。
   - `index.html` をブラウザで開き（開いていれば `F5` キーで更新）、数字や内容が反映されているか確認します。

## ✍️ `data.js` の編集方法

### 編集の基本ルール（3大原則）
1. **文字は必ず `""`（ダブルクォーテーション）で囲む**
   - ⭕ `"田中"` / `"結合テスト完了"`
   - ❌ `田中`
2. **数字は半角でそのまま入力する**
   - ⭕ `progress: 48` / `weeklyTasks: 9`
   - ❌ `progress: "48"` / `progress: ４８`
3. **項目の区切りには半角カンマ `,` を付ける**
   - 行を新しく追加したときは、前の行の末尾に `,` があるか確認してください。

---

### 1. 「経営判断が必要な事項」の追加・削除

画面最上部の赤枠内に表示されます。

#### 項目の書き方
```javascript
decisions: [
  {
    title: "基幹システムの代替ベンダー選定",       // 議題・決定してほしい内容
    decider: "社長",                             // 決める人（社長、担当役員など）
    deadline: "11/8まで",                        // 期限
    project: "基幹システム刷新"                   // 関連プロジェクト名
  },
  // 新しく追加する場合は、上のブロックをカンマ区切りで複製します
]
```

- **新しく追加する場合**:
  既存の `{ ... },` をコピーして直下に貼り付け、内容を書き換えます。
- **解決して削除する場合**:
  該当する `{ ... }` の数行を丸ごと削除します。

---

### 2. 「プロジェクト一覧」の追加・編集

#### 項目の書き方
```javascript
projects: [
  {
    name: "基幹システム刷新",                    // プロジェクト名
    status: "遅延",                              // 信号の手動指定 ("順調" / "注意" / "遅延" / 空欄 "")
    progress: 48,                               // 全体の進捗率（0〜100）
    milestone: "結合テスト完了",                 // 次のマイルストーン
    dueDate: "2026-11-12",                      // 期日（YYYY-MM-DD または MM/DD）
    owner: "田中",                              // 責任者
    comment: "外部ベンダーの納品遅れで2週間遅延", // ひとこと状況
    risks: [                                    // リスク・課題の箇条書き
      "ベンダー納品が2週間遅延 → 対応:代替ベンダーの打診中",
      "テスト要員が不足"
    ],
    tasks: [                                    // 主要タスク一覧
      "仕様変更の最終確認 (佐藤・11/6・遅延)",
      "テスト環境の構築 (鈴木・11/8)",
      "移行計画の策定 (田中・11/15)"
    ]
  },
  // 次のプロジェクト...
]
```

#### 🚦 信号（status）の判定ルール
- **手動で指定したいとき**:
  `status: "遅延"`、`status: "注意"`、`status: "順調"` と入力します。（手動指定が最優先されます）
- **自動判定させたいとき**:
  `status: ""`（空欄）にしておくと、マイルストーン期日と進捗率から自動計算されます。
  - **🔴 遅延**: マイルストーン期日を **7日以上超過** している場合
  - **🟡 注意**: 期日超過1〜6日、または **期日まで3日以内で進捗が遅れている** 場合
  - **🟢 順調**: 期日まで余裕がある、または期日直前でも進捗が順調（進捗100%含む）

---

### 3. 「担当者別の負荷」の編集

個人評価用ではなく、特定の人に負荷が集中していないかを把握し、業務の再配分を行うためのものです。

```javascript
members: [
  {
    name: "田中",          // 担当者名
    weeklyTasks: 9,        // 今週抱えているタスク数
    overdueTasks: 3,       // そのうち期限を超過しているタスク数
    loadPercentage: 95     // 負荷率% (90以上で赤、70以上で黄、それ以外は緑)
  },
  // ...
]
```
※上部の「期限超過タスク」KPIは、全担当者の `overdueTasks` を自動合計して表示します。

## 📢 役員・経営陣への共有方法

### 方法A: フォルダごと社内共有（推奨）
社内ファイルサーバー（共有フォルダ）、Teams、SharePoint、Google Drive 等に `dashboard` フォルダをそのまま配置します。
- 役員には「`index.html` をダブルクリックして開いてください」と伝えるだけです。
- 誰のPCでもブラウザ（Google Chrome, Microsoft Edge, Safari等）で即座に開けます。

### 方法B: 印刷・PDF保存して配布（会議用）
経営会議や役員報告で紙配布したい場合、またはPDFでメール送付したい場合の手順です。

1. 画面右上の **「🖨️ 印刷 / PDF」** ボタンをクリックします。（またはキーボードの `Ctrl + P`）
2. 印刷画面の設定を確認します：
   - **送信先**: 「PDFに保存」または社内プリンター
   - **レイアウト**: 「縦」（A4サイズ1〜2ページにぴったり収まる設計になっています）
   - **詳細設定（重要）**:
     - **「背景のグラフィック」にチェックを入れる**（プログレスバーや信号の色を印刷するために必須です）
     - **「余白」**: 「規定」または「なし」
3. **詳細を全部開いて印刷したい場合**:
   テーブル右上の **「すべての詳細を開く」** をクリックしてから印刷すると、全プロジェクトのリスクとタスクを展開した状態でPDF化できます。

### 方法C: Firebase Hosting でインターネット公開（Web URL共有）
役員がスマホやタブレット、外出先からWebサイトのようにアクセスできるようにする方法です。

#### 【初回のみ行うこと（3ステップ）】
1. **Firebase コンソールでプロジェクトを作成（無料）**:
   - [Firebase Console](https://console.firebase.google.com/) にアクセスし、「プロジェクトを追加」をクリック。
   - プロジェクト名を入力し（例: `company-management-dashboard`）、画面に従って作成を完了します。
   - 作成された「プロジェクトID」をメモします。
2. **Firebase CLI のインストール**:
   - Node.js / npm がある場合:
     ```powershell
     npm install -g firebase-tools
     ```
   - Node.js がない場合: [公式インストーラー (Windows用)](https://firebase.tools/bin/win/instant/latest) からダウンロードして実行します。
3. **Google アカウントでログイン**:
   - ターミナルで `firebase login` を実行し、ブラウザでログインします。

#### 【公開・デプロイ方法】
- **一番簡単な方法**: フォルダ内の **`deploy.bat` をダブルクリック** するだけです。
  （初回のみプロジェクトIDの入力を求められます）
- **コマンドで行う場合**:
  ```powershell
  cd "C:\Users\ntsurumaki\.gemini\antigravity\scratch\dashboard"
  firebase deploy --only hosting
  ```
デプロイが完了すると、専用の公開URL（`https://<プロジェクトID>.web.app`）が表示されます。役員にはこのURLを共有するだけで閲覧できるようになります。

#### 【毎週の更新方法】
1. `data.js` を編集して上書き保存します。
2. `deploy.bat` をダブルクリック（または `firebase deploy --only hosting` を実行）します。
3. 数秒でWeb上のダッシュボードが最新データに更新されます。

## ❓ トラブルシューティング

### Q1. `data.js` を保存したのに画面が変わらない
- ブラウザの「再読み込み」ボタンを押すか、キーボードの `F5`（Macは `Command + R`）を押してください。
- 変更した `data.js` が上書き保存されているか確認してください。

### Q2. 画面が真っ白になった / 「データ読み込みエラー」と表示される
`data.js` の書き方に誤り（文法エラー）がある可能性があります。以下をご確認ください：
1. 文字列を囲む `"` が抜けていませんか？（例: `name: 田中,` → `name: "田中",`）
2. 各行の末尾の `,`（カンマ）が抜けていませんか？
3. `{` と `}`、`[` と `]` のペアが崩れていませんか？
4. 直前に編集した部分を元に戻して再度保存してみてください。

### Q3. 文字化けして表示される
テキストエディタで保存する際、文字コードを **「UTF-8」** に指定して保存してください。
（Windowsの「メモ帳」で保存する場合、画面右下の文字コード欄で「UTF-8」を選択します）
